Roadmap

What Zod Agent ships today and what's next. We keep this page honest: shipped means shipped, planned means planned.

Currently shipped

Client-side agent loop

Done

Multi-round function-calling with streaming, retries, rate limits, timeouts, and a fallback provider.

Workflow execution harness

Done

Orchestration YAML runs as live multi-step workflows with tool grants, skill hints, and control flow.

Background service-worker agents

Done

Scheduled agents and workflows keep running when the tab is closed, while the browser is open.

Custom tools & structured output

Done

JavaScript tools in a sandbox, plus section markers rendered as rich cards with confirmation plans.

MCP over HTTP

Done

MCP servers over HTTP surface their tools in the agent loop. No local bridge daemon needed.

Scheduler, YAML, PWA

Done

Once/interval/daily/weekly tasks, aligned YAML config everywhere, and a PWA static build.

What's next

Multi-agent collaboration

Planned

The biggest roadmap gap — and the one thing Zod Agent can't do yet. True multi-agent collaboration means shared sessions where an orchestrator spawns per-step sub-loops with their own agent's provider and prompt, then merges the results. The data model for it exists; the runtime doesn't. This is the next major milestone.

Skills in plain chat

In progress

Skills currently exist as system-prompt hints inside workflow harnesses. The plan is to surface the same skills in the normal chat loop too — per-skill tool grants and full agent-loop support outside the orchestrator.

Always-on durability (chrome.alarms)

Planned

The service-worker scheduler runs while the browser is open, but a closed browser suspends it. For the Chrome extension build, the plan is to swap the scheduler onto chrome.alarms (fires on a one-minute minimum even when closed) and chrome.storage.local, so scheduled agents run even when the browser is fully shut.
